# dotfiles

One branch for all machines. Shared configs live in `shared/`; OS-specific overlays live in `pc/`, `linux/`, and `mac/`.

## Layout

```
shared/   # wezterm, yazi, starship, lazygit, fonts, tmux, snippets, git-prompt, git setup, AI config
pc/       # Windows nvim + PowerShell profile + wezterm-launcher + Windows-only AI hooks
linux/    # Linux nvim + zsh + waybar + wezterm-launcher
mac/      # macOS nvim + zsh + iTerm2 + Hammerspoon hotkeys + wezterm-launcher + script-selector
```

Machine-specific edits go in the matching overlay. Do not put OS-only files in `shared/`.

## Install

Clone into `~/.dotfiles`:

```bash
git clone https://github.com/mayorbyrne/dotfiles.git ~/.dotfiles
```

Then run the installer for your OS:

| OS | Installer |
|---|---|
| Windows | `pc/install/setup.ps1` (or double-click `pc/install/setup.bat`) |
| Linux (Ubuntu/apt) | `bash linux/install/setup.sh` |
| Linux (Arch/Omarchy) | `bash linux/install/omarchy.sh` |
| macOS | `bash mac/install/setup.sh` |

Installers also prompt for optional AI CLIs (Cursor `agent`, Codex, Claude). Choices are written to `~/.config/wezterm/ai_clis.txt`, and WezTerm opens a startup tab for each.
If any are chosen, `npx skills@latest add mattpocock/skills -g` installs those skills globally for the chosen CLIs.

## AI config

`shared/ai/` holds the hand-authored Claude Code, Codex, and Cursor config;
`pc/ai/` holds the Windows-only pieces. The installers call
`shared/install/setup_ai_config.ps1` (Windows) or
`shared/install/setup_ai_config.sh` (Linux/macOS), which symlinks:

| Repo path | Linked to |
|---|---|
| `shared/ai/AGENTS.md` | `~/.claude/CLAUDE.md` |
| `shared/ai/claude/keybindings.json` | `~/.claude/keybindings.json` |
| `shared/ai/claude/commands/i18n-extract.md` | `~/.claude/commands/i18n-extract.md` |
| `shared/ai/claude/skills/release-docs` | `~/.claude/skills/release-docs` |
| `pc/ai/claude/hooks/statusline.ps1` | `~/.claude/hooks/statusline.ps1` (Windows only) |
| `shared/ai/AGENTS.md` | `~/.codex/AGENTS.md` |
| `shared/ai/codex/rules/default.rules` | `~/.codex/rules/default.rules` |
| `shared/ai/codex/skills/artisan-mode` | `~/.codex/skills/artisan-mode` |
| `shared/ai/AGENTS.md` | `~/.cursor/AGENTS.md` |
| `shared/ai/AGENTS.md` | `~/.cursor/rules/AGENTS.mdc` |

Two files are written rather than linked, so work-specific entries stay out of
this repo:

| Repo path | Written to | Overlay (outside the repo) |
|---|---|---|
| `shared/ai/claude/settings.json` | `~/.claude/settings.json` | `~/.config/dotfiles/claude.work.json` |
| `shared/ai/codex/config.toml` | `~/.codex/config.toml` | `~/.config/dotfiles/codex.work.toml` |

- Claude: the script deep-merges the overlay over the repo file with `jq` (or
  `ConvertFrom-Json` on Windows). Rerun it after changing either file. If the
  overlay is missing, the script offers to create one by prompting for a plugin
  marketplace name, git URL, and plugin list.
- Codex: seeded once, as the repo file plus the overlay appended, then left
  alone because Codex rewrites the file itself. The overlay must hold only
  `[tables]`, no top-level keys. Delete `~/.codex/config.toml` to reseed.
- `AGENTS.md`: uses `@work/*` as a placeholder for the employer npm scope. If
  `~/.config/dotfiles/work.env` sets `WORK_NPM_SCOPE=@yourscope`, the four
  `AGENTS.md` targets are written as copies with the scope swapped in, so rerun
  the script after editing `AGENTS.md`. Without `work.env` they stay symlinks.
  The script prompts for the scope when the file is missing.

`shared/ai/AGENTS.md` is the single source for global agent instructions. Cursor
picks it up as a machine-local user rule under `~/.cursor/rules/`. Account-synced
User Rules in Customize -> Rules are a separate store; leave them empty or they
will stack on top of the file.

Links are made per file and per skill, not per directory, so the tool-generated
neighbours in the same folders (`~/.claude/skills/synced/`,
`~/.codex/skills/.system/`, `~/.cursor/skills-cursor/`, plugin-provided
symlinks) stay untouched.

Existing real files are moved to `<path>.bak-<timestamp>` before linking. Nothing
is deleted blind. Windows symlinks need Developer Mode on, or an elevated shell.

What never syncs: `~/.claude/.credentials.json`, `~/.codex/auth.json`,
`~/.cursor/cli-config.json`, session and history files, caches, editor
`History/` / `workspaceStorage/` / `globalStorage/`, and the overlays above.
Credentials are regenerated by logging in on the new machine. Cursor already
loads the Claude and Codex skill links, so those are not duplicated under
`~/.cursor/skills/`.

Plugins are not copied in. The merged `settings.json` declares
`extraKnownMarketplaces` and `enabledPlugins`, so Claude Code installs them from
the marketplace repo on first run.

Machine drift:

- `~/.claude/settings.local.json` is not a user-level file. Claude Code only
  reads `settings.local.json` inside a project's `.claude/` folder, so
  per-machine overrides go in `~/.config/dotfiles/claude.work.json` instead.
- The synced `statusLine` runs `statusline.ps1` and is guarded by a file test, so
  it is a no-op on Linux and macOS. Override it in the Claude overlay there.
- Claude Code rewrites `~/.claude/settings.json` in place. Those edits
  stay on the machine. Copy anything worth keeping into the repo file or the
  overlay, then rerun the script.
- Cursor editor settings live at `%APPDATA%\Cursor\User\settings.json` (Windows),
  `~/Library/Application Support/Cursor/User/settings.json` (macOS), or
  `~/.config/Cursor/User/settings.json` (Linux). They are not linked yet: this
  machine only has the default file. Same for `~/.cursor/mcp.json` and
  `~/.cursor/hooks.json` until there is hand-authored content to sync.

After that, configure git:

- Windows: `shared/install/setup_git.ps1`
- Linux / macOS: `bash shared/install/setup_git.sh`

This sets user and credentials, and adds an `[include]` of
`shared/git/gitconfig` to `~/.gitconfig` for settings shared across machines
(editor, `autocrlf = false`, push, lfs). Put shared git settings in that file,
and per-machine ones in `~/.gitconfig`. Rerunning is safe; the include is only
added once.

Existing machines that already cloned this repo need a re-run of their installer (or manual recreation of symlinks) after pulling this layout — old paths like `.dotfiles/nvim` no longer exist.
